## Purpose

Teach Rashad how strong long-form proposals progress across pages without turning historical proposals into templates.

## Narrative archetypes

### `NAR-UNDERSTAND-RESPOND`
`Client context/evidence → engagement interpretation → response architecture`

### `NAR-GAP-TARGET`
`Current state → diagnosed gap → target state → transition`

### `NAR-REQ-METHOD-OUTPUT`
`Requirement → method → output → acceptance/proof`

### `NAR-PHASE-GATE`
`Phase promise → activities → tools → deliverables → completion gate`

### `NAR-WORKSTREAM-SYSTEM`
`Workstreams → dependencies → integrated outcome`

### `NAR-CLAIM-PROOF-RELEVANCE`
`Claim → evidence → relevance to current criterion/opportunity`

### `NAR-THESIS-DETAIL-CONTROL`
`Executive thesis → analytical detail → governance/measurement/control`

## Sequence guidance

Default evaluator-first order for client proposals when the RFP does not mandate another order:

`Client understanding → strategic interpretation → solution/method → delivery plan → evidence/experience → team → governance/quality → appendices`

Do **not** place generic company profile/credentials before client understanding merely because historical proposals did so. RFP-mandated order still wins.

## Non-cloning rule

Historical section order, wording, layouts, client facts, logos and page coordinates are never copied. Only the abstract narrative relationship may be reused.
