# Golden Visual Master Page-by-Page Workflow

STATUS: ACTIVE PRIMARY VISUAL WORKFLOW — v2.6.4.4

## Phase 0 — plan the whole deck before generating pages
1. complete RFP Summary content/depth architecture;
2. determine all physical pages dynamically;
3. assign page families and artifact families;
4. create Deck Visual DNA;
5. create/approve 3–5 Style Anchors;
6. create section anchors / Golden Section Boards as needed;
7. initialize Deck Continuity Ledger.

## Phase 1 — page generation loop
For PAGE-N:
1. compile approved page intelligence/topology;
2. load persistent Deck anchors;
3. load Section Anchor;
4. load PAGE-(N-1) master if available;
5. include PAGE-(N+1) relationship intent when useful;
6. generate one Golden Visual Master;
7. run visual/artifact/continuity council;
8. reject weak/card-default/drifted master;
9. freeze master hash.

## Phase 2 — final native overlay
1. reserve/confirm text zones;
2. overlay exact production copy and Arabic-Indic numerals;
3. overlay exact Rubix | Client co-brand on the same physical line using optical sizing;
4. add page/footer/source labels;
5. no artifact reconstruction.

## Phase 3 — QA/export
1. run executable HTML/page QA when available;
2. verify master provenance/underlay placement;
3. verify text fit/RTL/brand/overflow;
4. export PDF/PPTX from same final composition;
5. parity-check final renders;
6. release only when required gates pass.

## Long-deck continuity
Generate in batches of 4–6 pages. After each batch run continuity review against all anchors and at least the immediately previous batch. Continuing in a later turn requires the saved anchors/ledger; do not depend on conversational memory alone.

## v2.6.4.6 executable QA handoff
After Phase 2, compile each locked Canonical Page Spec through the v1.2 Page-Spec→QA-Spec compiler. For GVM pages compile a hashed semantic topology sidecar and require G13/G14. Run per-page HTML QA until `HTML_PREEXPORT_PASS`; then export PDF/PPTX and run raster parity. Run deck-level continuity over the full ledger. Final release requires the evidence aggregator plus applicable Rashad councils.
