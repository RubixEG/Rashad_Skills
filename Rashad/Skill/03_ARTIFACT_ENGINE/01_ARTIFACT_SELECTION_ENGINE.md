# Artifact Selection Engine

## Selection sequence
1. Identify evaluator question.
2. Write the one-sentence page thesis.
3. Identify supporting claims and evidence.
4. Determine the dominant information relationship.
5. Identify the service-line owner.
6. Retrieve three strong benchmark pages matching archetype, relationship, and density.
7. Select or design the artifact.
8. Validate density, RTL, editability, and section rhythm.

## Relationship to artifact family
- hierarchy → pyramid, tree, layered model, capability stack
- sequence → lifecycle, process spine, stage gates, journey
- time → roadmap, Gantt, waves, milestones, critical path
- system/network → ecosystem, architecture, integration map
- comparison → matrix, benchmark, options, before/after
- ownership → RACI, decision rights, role-output map
- cause/effect → issue tree, causal chain, driver tree
- risk/control → heatmap, bow-tie, control map, assurance model
- decision → funnel, choice cascade, prioritization matrix
- evidence → evidence wall, case map, proof chain
- value → value tree, benefits bridge, business case
- dependency → dependency network, interlock, critical path
- maturity → maturity ladder, heatmap, transition roadmap
- quantitative → chart, waterfall, scorecard, distribution

## Anti-card rule
Cards may support a page but cannot replace the correct relationship. A row of boxes is not a lifecycle, governance model, architecture, risk model, or strategy.

## Bespoke composition rule
Create a bespoke page when:
- no registered artifact fits;
- the page combines two essential relationships;
- the RFP has a unique evaluation or contractual logic;
- a critical executive page needs a stronger synthesis.

The bespoke page must still be editable, benchmarked, and graded.

## v7.6 non-regression requirement
Artifact selection is not complete until ART-NR-001 passes. If a safety repair changes the selected artifact family, the page must return to selection and council review rather than silently accepting a generic fallback.
