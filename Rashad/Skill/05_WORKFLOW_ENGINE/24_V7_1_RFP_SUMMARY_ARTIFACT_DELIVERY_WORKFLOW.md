# V7.1 — RFP Summary Artifact Delivery Workflow

**STATUS: CURRENT RFP SUMMARY ARTIFACT DELIVERY WORKFLOW — SUPERSEDES VISUAL STEPS 9–15 OF V7.0.2 WHERE CONFLICTING**

Steps 1–8 of `23_V7_RFP_SUMMARY_DECISION_WORKFLOW.md` remain valid for ingestion, role planning, consulting cognition, councils, content packs and semantic graphs.

9. For every critical page, generate exactly **5 materially different communication strategies** across ≥3 families, including at least one minimal/non-diagram strategy. RING/HUB/SPINE/STACK/LANE are not hypotheses.
10. Produce five page-specific **concept renders** for search evidence. They are internal only; each must have a distinct hash and Visual Concept brief. Concept renders cannot be user-visible masters.
11. Run Artifact Skeptic + independent concept critique where available. Select a concept on communication fitness/simplicity, never candidate position. Missing live judge may preserve internal concept work but cannot authorize user-visible output.
12. Translate the winning concept into page-specific Art Direction and produce a real `PRODUCTION_PAGE_RENDER`. The production renderer may use native elements, generated imagery, charts, tables, typography or relational geometry as the concept requires. It must not degrade unsupported forms into generic cards/boxes.
13. **Framework QA cannot substitute for actual-output QA.** Run independent actual-pixel page QA on the exact production-render hash. Any failed dimension generates a Repair Brief and mandatory re-render. A `USER_VISIBLE_ARTIFACT_DRAFT` requires final pixel PASS and a **closed repair loop**; `DRAFT_QA_PARTIAL` is internal only.
14. Assemble the deck only from production pages that passed page QA. Render the actual PPTX to pixels, create a montage, run deck-level Partner/Artifact-Skeptic/Information-Design/RTL/Brand QA, deterministic product inspection, and repeat repair if needed.
15. Create an exact-file Delivery Dossier and run the User-Visible Delivery Gate. Only after `DELIVERY_ALLOWED` may the PPTX/PDF be handed to the user. `RELEASE_CANDIDATE/RELEASED` require the additional independent/parity/proof/release-chair evidence.

## Hard anti-shortcut
Markdown/content → direct PPTX is forbidden for artifact-mode RFP Summary. If production rendering or actual-output QA cannot be executed, return content/internal concept evidence and state the limitation; do not manufacture a generic presentation as a fallback.
