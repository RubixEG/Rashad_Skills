## Current output classes
- `CONTENT_DRAFT` — evidence-backed content only; no artifact claim.
- `INTERNAL_CONCEPT_DRAFT` — internal communication-strategy / concept-search evidence only; **never user-visible as the delivered artifact**.
- `USER_VISIBLE_ARTIFACT_DRAFT` — actual `PRODUCTION_PAGE_RENDER`, independent actual-pixel QA PASS bound to the exact render hash, repair closure, deck product QA where applicable, and exact-file Delivery Certificate. Visible Draft marking is allowed.
- `RELEASE_CANDIDATE` — user-visible artifact requirements plus current-engagement independent release evidence, proof index and export parity.
- `RELEASED` — only `RASHAD_BRAIN_RELEASE_CHAIR` may issue.

Legacy `ARTIFACT_DRAFT` resolves to `USER_VISIBLE_ARTIFACT_DRAFT`; it **cannot** mean an internal concept render or a partial-QA wireframe.

## Search diversity foundation
Every critical page requires exactly five initial **communication-strategy hypotheses**, not five geometry variants. Search evidence must include:
- five materially different strategies across at least three communication families;
- at least one minimal/non-diagram candidate;
- five distinct internal concept-render hashes tied to the page fingerprint;
- no positional/H1 default;
- no reuse of a fixed five-skeleton set across unrelated pages.

Concept renders are search evidence only. They are not production pages and do not satisfy user-visible delivery.

## Missing live judge behavior
Missing live independent release judging must not suppress **internal** exploration. It does, however, prevent release escalation. It never authorizes an unreviewed concept wireframe for user-visible delivery.

## Actual-output truthfulness
Framework certification is not actual-output QA. A user-visible artifact must prove actual production pixels, exact-hash independent pixel review, repair closure, deck-level review when applicable, and exact-file delivery authorization. Missing pixel review is `BLOCK_DELIVERY`, not a warning-only user-visible path.
