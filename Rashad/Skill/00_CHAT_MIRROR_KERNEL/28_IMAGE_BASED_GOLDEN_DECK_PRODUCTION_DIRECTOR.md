# Image-Based Golden Deck Production Director

STATUS: APPROVED FALLBACK / VISUAL-REFERENCE DIRECTOR — superseded as default by v2.6.4.9
BASELINE: v2.6.4.6 + QA Harness v1.2

## Mission
Restore the proven MWAN-quality production route: generate/approve each slide as a full-page Golden Visual Master, then project the same approved raster page into PDF, PPTX visual-mirror and HTML/image-based outputs without rebuilding the artwork into weak native cards.

## Core production principle
**The renderer preserves the approved page image; it does not redraw the artifact.**

For visual-fidelity deliverables, the Golden Visual Master is the page's visual authority. Native rendering is limited to governed overlays, export containers, QA evidence and optional editable reconstruction pilots.

## Legacy GVM route when explicitly selected
1. RFP intelligence and role/page planning.
2. Artifact Intelligence and Consulting Visual Excellence.
3. Deck Visual DNA and Style Anchor Set.
4. Page-by-page Golden Visual Master generation.
5. Visual/Artifact/Continuity Council.
6. Freeze page image with SHA-256 and manifest.
7. Apply exact native overlays where required.
8. Flatten to final approved page image when exact visual delivery is the target.
9. Render image-based PDF, visual-mirror PPTX and optional image-based HTML.
10. Run QA Harness v1.2 plus image-deck parity/continuity gates.

## Explicit conflict resolution
Older image-isolation rules that reject every full-page image are superseded for this mode. The correct rule is:

**Full-page Golden Visual Master generation is allowed when it is declared as a visual-master page, governed by Page Spec, Style Anchors, QA admission, and SHA freeze. It is not an uncontrolled final-answer image and must not fabricate authoritative facts.**

## What the Golden Master may contain
Allowed when relevant and council-approved:
- Saudi/public-sector visual context, including flags and institutional scenes;
- people, operations, devices, screens and dashboard-like visuals;
- complex artifact compositions, visual architectures, flows, journeys and analytical metaphors;
- high-density consulting layouts when readable and intentional;
- cards as supporting objects inside a larger analytical page system.

## What it must not do without explicit QA approval
- create a fake Rubix or client logo and treat it as authoritative;
- invent official dates, tender IDs, amounts, scores or source facts;
- introduce unreadable/garbled Arabic or mixed-direction text;
- become a generic card grid when the page requires a system, journey, architecture, network, roadmap or evidence model;
- drift from the Deck Visual DNA or style anchors.

## Best-practice modes
### Mode A — Full Raster Master
The page is generated as a complete raster page and accepted only after visual/text/brand QA. Fastest, highest visual richness, least editable.

### Mode B — Hybrid Flattened Master (recommended for production accuracy)
Generate the visual/artifact underlay, overlay exact native text/logos/page chrome, then flatten the result into the final page raster used by PDF/PPTX/HTML. Highest balance of quality and factual/brand control.

### Mode C — Native Editable Reconstruction
Build a separate editable PPTX from semantic contracts and compare against the Golden Master. This is a secondary editable pilot, not the pixel-fidelity source.

## Release truth
Image-based PDF/PPTX may be production-visual PASS when all relevant raster, brand, text, continuity and parity gates pass. Fully editable parity is a separate workstream and must not be claimed from image-based slides.

## v2.6.4.9 status
This director is retained as an **approved fallback / visual-mirror route**, not the default production route. The current default is the consulting visual search → HTML/SVG/CSS master workflow. Do not route to image-only production merely because it is easier.
