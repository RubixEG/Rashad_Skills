# 33 — Artifact Engine Acceptance Tests v2.3

STATUS: TEST SPECIFICATION + KNOWLEDGE REGRESSION GATE
NOTE: Rendering tests execute only when an external deterministic production runtime exists. Written policy tests are not falsely labeled render execution.

## A. Meaning / topology tests
1. Every analytical page has a material executive/evaluator question.
2. Every page has one explicit thesis.
3. Every selected artifact has a dominant information relationship.
4. Semantic nodes and edges are declared before visual design.
5. Generic-card fallback is rejected for relationship-heavy content.
6. Artifact family change after lock requires a new Artifact Council approval.

## B. Image ideation tests
1. Image generation never receives a request to create the final slide/page.
2. `INTERNAL_VISUAL_CONCEPT` contains no production text/logos/numbers/client facts.
3. Concept images are never embedded as analytical final pages.
4. Production visual ingredients are strictly text/logo/number/fact-free.
5. All authoritative text/data remain native.

## C. Brand / RTL / numeral tests
1. Exact current Rubix asset provenance required.
2. No generated/reconstructed logo.
3. No black/near-black page background.
4. Arabic sequence begins physically on the right.
5. Arabic prose uses Arabic-Indic numerals under current user authority.
6. LTR technical tokens remain isolated, not reversed.

## D. Narrative tests
1. Same dominant layout family not repeated mechanically.
2. Page adds a new conclusion/proof/decision/implementation detail.
3. High-density pages preserve legibility and may paginate instead of shrinking excessively.
4. Visual emphasis tracks materiality, not decoration.

## E. Non-regression tests against v2.2
1. Exact R-code shard count remains 388.
2. Scope shard count remains 96.
3. Scope-mapping shard count remains 96.
4. Root YAML frontmatter remains parseable.
5. Unified state vocabulary unchanged.
6. Parallel workflow authority unchanged.
7. RFP Summary, Risk/Clarification Council, current Brand Authority, and Production Firewall are not superseded by visual reference knowledge.
8. No PDF/Python/JSON/PPTX/font/HTML/CSS files are introduced.

## Release rule
Any failed A/B/C/E test blocks V2.3 release. D failures require remediation or documented Council exception unless a higher RFP/user requirement justifies the composition.
