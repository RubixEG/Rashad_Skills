# Cover and Section-Opener System — Current Hard Lock

## Cover
Every RFP Summary cover uses a **new generated hero image** tailored to the current competition unless the user explicitly opts out.

The image is an ingredient, never the final slide.

Required production chain:
`RFP theme → cover thesis → text-free hero image brief → generated hero asset → deterministic crop/facet → native title/subtitle/reference/date → verified Rubix logo → validated client logo → QA`.

### Hard prohibitions
- no generated Rubix/client logo;
- no generated text, numbers, dates or tender IDs as production truth;
- no black/near-black full-slide background;
- no baked screenshot cover;
- no old logo/deck device;
- no KPI dashboard on the cover;
- no generic city skyline unless the engagement actually warrants it.

### Cover families
Artifact Engine selects from relationship/purpose, not template name:
1. generated sector hero + faceted crop;
2. generated conceptual hero + controlled Rubix device;
3. institutional/environment hero with strong whitespace.

All families remain light-first and low-density.

## Section opener
Use a light canvas, exact section label/name, one thesis/promise, one visual anchor, and restrained palette. No dark divider slides.
