# V3 Predictive Failure Council

Purpose: predict the failures that historically appeared after delivery, before the page is generated.

Council roles:
- McKinsey-style answer-first exhibit reviewer;
- BCG-style transformation architecture reviewer;
- Deloitte-style operating model reviewer;
- Saudi government technical evaluator;
- Proposal director;
- Senior project manager;
- Content evidence lead;
- Artifact topology lead;
- RTL/BiDi engineer;
- Brand/prepress lead;
- QA/regression engineer;
- Runtime integration lead.

Predictive checklist:
- Will this become cards because the relationship is underspecified?
- Will the cover image still make sense if the title is removed?
- Is the content pack rich enough to justify an artifact?
- Does the page family have a MWAN/corpus anchor?
- Will the renderer need SVG relationships rather than div boxes?
- Could repair remove nodes/edges/evidence?
- Could fonts produce tofu/broken glyphs?
- Could internal/debug text leak to the client?
- Could the deck repeat the same grammar for many pages?
- Does the page use more colors than the palette budget?
- Can PDF/PPTX be verified from the same master raster?

If any risk is high, the page must be redesigned before rendering.
