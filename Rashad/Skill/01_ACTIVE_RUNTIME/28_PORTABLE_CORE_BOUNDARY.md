# 28 — Portable Knowledge Core Boundary

STATUS: HARD AUTHORITY — CURRENT

## Purpose
This package is a **tool-agnostic knowledge/decision OS**, not a bundled application runtime.

The portable core intentionally contains:
- Markdown authorities and exact prompt knowledge;
- approved current Rubix raster logo/device assets;
- artifact, workflow, council, QA, brand, RFP intelligence, and firm-knowledge rules.

The portable core intentionally does **not** contain:
- PDF binaries;
- Python/PYC;
- JSON runtime state or schemas;
- CSS/HTML renderer implementation;
- font binaries;
- PPTX templates;
- client-specific appendix binaries;
- generated engagement runs.

## Historical implementation references
Any migrated text that mentions an old `runtime/...`, `RASHAD_CANONICAL_KNOWLEDGE/...`, Python, JSON, or other implementation path is **provenance only** unless that referenced object is actually present in this package.

Never:
- assume an absent implementation component exists;
- claim a renderer, state machine, database, API, or PPTX compiler ran because an old source once referenced it;
- search for or reconstruct absent code from memory;
- fall back to a generic renderer and call it Rashad output.

## Execution rule
Use the conceptual contract expressed in the Markdown authorities. When the target environment provides an external deterministic composer that supports native text and exact asset injection, execute under current gates. Generic image/render tools alone are insufficient. Otherwise return the structured content/page/artifact specification and identify the missing production dependency.

## Source precedence
This boundary does not weaken exact Rashad prompt content. It only separates **knowledge authority** from obsolete/missing implementation plumbing.

## v2.1 production boundary
Availability of an image-generation tool is **not** evidence that Rashad production capability exists. Image generation cannot substitute for a deterministic composer with native text and exact asset injection. If only image generation is available, Rashad may produce a text-free visual ingredient but must not label a full-slide image as a Rashad artifact.
