# 26 — Visual Archetype Library v1

STATUS: ACTIVE KNOWLEDGE — v2.3
SOURCE: normalized from audited Rubix/history knowledge plus the 21-image generated visual reference corpus. Source images are **not bundled** and are never production authority.

## Rule
An archetype is an **abstract cognitive composition**, not a reusable slide template. It defines when a visual pattern is useful, what relationships it must preserve, and what it must not become.

## VAI-01 — Editorial Sector Hero
**Use when:** cover or major section opener requires one visual metaphor/sector context.
**Relationship:** narrative framing, not analytical proof.
**Must show:** one clear focal scene or metaphor; controlled negative space for native text overlay.
**Never:** baked text, logos, numbers, dates, client facts, full-slide generated production.

## VAI-02 — Executive Competition Pulse
**Use when:** management must understand the opportunity in 10 seconds.
**Relationship:** executive synthesis (`REL-PULSE`).
**Structure:** one central thesis/anchor + 3–5 material dimensions (scope, delivery, win, readiness, exposure).
**Avoid:** KPI-dashboard aesthetic with many equal cards.

## VAI-03 — Navigation Journey Map
**Use when:** TOC or section navigation should reveal the logic of the argument.
**Relationship:** `REL-NAV + REL-SEQ`.
**Structure:** numbered journey with meaningful chapter labels and clear physical RTL order for Arabic.
**Avoid:** decorative circles that do not map to actual reading order.

## VAI-04 — Bid Journey / Stage Spine
**Use when:** activities progress through sequential bid or delivery gates.
**Relationship:** `REL-SEQ`, optionally `REL-TIME`.
**Structure:** continuous spine + gates + decisions + outputs.
**Avoid:** isolated boxes with no progression.

## VAI-05 — Opportunity Snapshot + Critical Dates
**Use when:** concise facts and temporal pressure must be read together.
**Relationship:** `REL-PULSE + REL-TIME`.
**Structure:** executive fact block + one critical timeline/countdown.
**Avoid:** six unrelated date cards.

## VAI-06 — Gap / Readiness Synthesis
**Use when:** current readiness, gaps, and actions must drive a management decision.
**Relationship:** `REL-COMP + REL-DEC`.
**Structure:** what is ready / what is missing / what decision or action follows.
**Avoid:** long issue list with no prioritization.

## VAI-07 — Deliverable Operating Roadmap
**Use when:** outputs form an ordered operating system or sequence.
**Relationship:** `REL-SEQ`, optionally `REL-DEP`.
**Structure:** outputs aligned to phases, owners, or acceptance logic.
**Avoid:** raw BOQ repetition.

## VAI-08 — Role-to-Requirement / Team Readiness Matrix
**Use when:** roles must be evaluated against experience, quantity, qualifications, workstreams, or evidence.
**Relationship:** `REL-OWN + REL-COMP`.
**Structure:** roles on one axis; requirements/evidence/readiness on the other.
**Avoid:** biography-only team cards.

## VAI-09 — Evaluation-to-Win Architecture
**Use when:** evaluation criteria must translate into proposal strategy.
**Relationship:** `REL-EVID + REL-DEC`.
**Structure:** criterion/weight → evaluator belief → proposal response → evidence.
**Avoid:** copying evaluation table without strategic interpretation.

## VAI-10 — Risk / Clarification Decision Register
**Use when:** risks or clarifications must show materiality and decision effect.
**Relationship:** `REL-RISK + REL-DEC`.
**Structure:** issue → trigger/cause → material impact → treatment/question → owner/decision.
**Avoid:** generic tender observations or unprioritized question lists.

## VAI-11 — Procurement / RFP Maturity Assessment
**Use when:** source quality creates estimation or delivery uncertainty.
**Relationship:** `REL-MAT + REL-RISK`.
**Structure:** maturity dimensions + evidence + confidence/implication.
**Avoid:** criticizing the client; frame as bid-estimation confidence.

## VAI-12 — Multi-Track Critical Path / Gantt
**Use when:** parallel workstreams, locks, freezes, dependencies, and milestones matter.
**Relationship:** `REL-TIME + REL-DEP`.
**Structure:** time axis + parallel tracks + gates + critical dependencies.
**Avoid:** decorative timelines that do not encode duration/dependencies.

## VAI-13 — Operating Capability Ecosystem
**Use when:** multiple capabilities form an integrated operating system.
**Relationship:** `REL-SYS + REL-HIER`.
**Structure:** core purpose/capability surrounded by connected components, flows, or layers.
**Avoid:** radial circles without meaningful edges.

## VAI-14 — Current → Target Transformation Architecture
**Use when:** transformation from current state to future state is central.
**Relationship:** `REL-MAT + REL-SEQ`.
**Structure:** current constraints → transition mechanisms → target capabilities/outcomes.
**Avoid:** before/after panels that omit the transformation mechanism.

## VAI-15 — Evidence / Qualification Readiness Architecture
**Use when:** qualification evidence must be connected to submission requirements and win conditions.
**Relationship:** `REL-EVID + REL-COMP`.
**Structure:** requirement → evidence source → readiness → gap/action.
**Avoid:** certificate screenshot walls.

## Selection rule
Choose an archetype only after the dominant relationship is classified. If none fits without losing meaning, design a bespoke artifact and register its logic rather than forcing a catalog match.


## v2.5 deterministic extensions

### VAI-27 — Cause-to-Intervention Tree
**Use when:** causes/drivers must connect to problems and interventions.
**Relationship:** `REL-CAUSE`.
**Structure:** root issue/outcome → causal drivers → controllable levers/interventions.
**Avoid:** unsupported causal claims or decorative issue trees.

### VAI-28 — Risk-Control Topology
**Use when:** controls, prevention, detection, recovery or ownership topology matters more than a row-based register.
**Relationship:** `REL-RISK + REL-OWN/REL-CAUSE`.
**Structure:** causes/triggers → risk event → impacts → preventive/detective/recovery controls → owners.

### VAI-29 — Decision Gate / Choice Cascade
**Use when:** choices narrow through criteria/conditions to a management decision.
**Relationship:** `REL-DEC`.
**Structure:** alternatives/conditions → filters/gates → recommendation → conditions/actions.

### VAI-30 — Value-Creation Tree / Benefits Bridge
**Use when:** value sources or benefits accumulate from capabilities/actions to outcomes.
**Relationship:** `REL-VAL`.
**Structure:** value levers → intermediate benefits → measurable outcomes; use a bridge only when quantitative evidence exists.
**Avoid:** invented benefits or unquantified waterfall values.

### VAI-31 — Quantitative Evidence View
**Use when:** actual supported numbers require a chart/scorecard/trend/distribution/bridge.
**Relationship:** `REL-QUANT`.
**Selection sub-rule:** choose chart topology from the quantitative question (trend, comparison, composition, distribution, bridge). No chart without evidence and unit semantics.
