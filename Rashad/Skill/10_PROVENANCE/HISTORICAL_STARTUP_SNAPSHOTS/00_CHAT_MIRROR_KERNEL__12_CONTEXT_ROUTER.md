# Context Router / Compiler — Selective Loading Contract

STATUS: ACTIVE

## Goal
Recreate the useful effect of the long live chat by compiling the **smallest authoritative task context** instead of relying on retrieval across hundreds of files.

## Always-on kernel
Always retain:
- Bootstrap;
- Owner Policy;
- Authority Graph;
- Product Registry;
- Decision Ledger summary/status rules;
- No-Unnecessary-Clarification policy.

## Routing procedure
1. Classify the requested Rashad product.
2. Reset/identify the current engagement.
3. Load current RFP/evidence relevant to the product.
4. Load the canonical product/workflow authorities.
5. Load only relevant councils/service-line modules.
6. Resolve exact R-code plan; retrieve only required exact prompt shards.
7. Load Artifact/brand/RTL/production modules only when required by the requested/default product.
8. Add applicable ACTIVE decisions from the ledger.
9. Exclude historical/superseded/rejected decisions from active context.
10. Before asking the user, apply the no-clarification gate.

## Product bundles
### RFP Summary
`Owner Policy + RFP Summary product + RFP ingestion/evidence + Risk/Clarification Council + authorship maturity + Artifact Intelligence + Arabic/brand/production gates`.

### Full proposal
`Owner Policy + proposal workflow/skeleton + compliance/bid strategy + scope/R-code plan + section dependencies + evidence + relevant service-lines/councils + Artifact Intelligence + production gates`.

### One section
`Owner Policy + section contract + upstream approved objects + exact required prompts + current evidence + relevant artifact/brand rules`.

### Reference-corpus analysis
`Reference Policy + Artifact/Proposal Intelligence extraction rules`; explicitly exclude current engagement fact contamination and old brand activation.

## Anti-bloat rule
Never load all 388 prompt bodies, all historical proposals, raw chat transcript, all service-line playbooks, all appendix assets or all QA modules merely because they exist.
