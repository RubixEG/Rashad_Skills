# Section-by-Section Generation — Portable Current Workflow

## Readiness
No substantive section cycle starts until its Dependency Ledger derives `READINESS=READY`.

The exact first reader section may vary when the RFP mandates structure, but production still begins with the earliest dependency-ready substantive content rather than the Executive Summary.

## Each section cycle
1. resolve RFP-mandated vs house structure;
2. display status/dependency report;
3. establish the Section Contract;
4. retrieve exact Rashad prompt blocks and current evidence;
5. generate structured section content;
6. create Page / Artifact Intent Contracts;
7. select artifact family from the information relationship;
8. use only approved abstract patterns from the External Proposal Reference Session when helpful;
9. create explicit Arabic sequence contracts where ordered;
10. create visual-asset briefs where imagery adds material value;
11. apply current Rubix palette/theme rules after artifact intent is stable;
12. render **only if the target environment provides an appropriate renderer/tool**;
13. validate every produced representation for geometry, RTL, numeral style, semantic preservation, brand, and evidence;
14. run section/council/compliance/evidence grades;
15. obtain user/owner approval or revisions;
16. store approved version and propagate dependency impacts.

## Fail-closed rendering rule
Never substitute a generic card deck, generic HTML report, direct PDF, or invented Rubix theme merely because the intended rendering tool is unavailable.

If rendering is unavailable, return the approved content + page contracts + visual specs and state the exact production dependency that is missing.

## Artifact-strength rule
Safety checks are necessary but not sufficient. A section cannot become approved if safety repair weakens its argument, deletes semantic nodes/edges, or replaces an appropriate system/sequence/hierarchy artifact with generic cards.

## v2.6.4 multi-page section visual workflow
When a section requires two or more analytical pages, complete all page analytical contracts first, then run `10_SECTION_LEVEL_GOLDEN_BOARD_WORKFLOW.md`. Generate one reference-only Golden Section Board for the related pages, freeze the Section Visual Charter, derive page visual targets, and only then enter native geometry/composition. Do not independently redesign each page during HTML/PDF/PPTX mapping.
