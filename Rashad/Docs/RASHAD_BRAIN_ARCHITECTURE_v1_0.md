# Rashad Brain v1.0 — Consulting Intelligence Operating Architecture

## Executive position
Rashad should not be treated as a large prompt, a Skill pack, a renderer, or a collection of personas. The operating model is a layered cognitive system bound to the v7.0.2 knowledge/authority baseline.

## System boundaries
- **Skill v7.0.2**: authority, knowledge, 388 R-codes, 96 scopes, 96 mappings, role contracts, naming, consulting doctrine.
- **Brain Runtime v1.0**: blackboard state, council routing, production/challenge/dissent/judgment orchestration, causal reasoning, memory, meta-cognition and release authority.
- **QA Runtime v4.1**: deterministic measurement, failure taxonomy, evidence/proof validation, stress and parity.
- **Renderer**: geometry, routing, typography, pixels and projections.
- **Live provider layer**: actual model invocations. If absent, brain state is NOT_EXECUTED/BLOCKED; it cannot be simulated by a PASS JSON.

## Cognitive loop
`Ground → Frame → Produce → Challenge → Counterfactual → Reconcile → Lock → Synthesize → Render Search → Judge → Stress → Repair → Judge Again → Meta-Review → Release`

## Blackboard model
Every engagement/page works against an append-only blackboard containing:
- source/evidence references and hashes;
- facts, inferences, assumptions and recommendations;
- management/evaluator questions;
- cognitive packet and semantic graph;
- council invocations and findings;
- explicit dissent and its disposition;
- decisions and dependencies;
- render candidates and judge evidence;
- QA evidence and release state;
- hash lineage so stale outputs are detectable.

These are not 16 personas loaded into one prompt. Each is a question/authority bundle routed only when relevant and mapped to existing authorized v7 lenses.

## Important new brains
### Epistemic brain
Knows the difference between fact, inference, assumption, recommendation, confidence and unknown. Requires material claims to have traceable proof and actively looks for contradiction/falsification.

### Causal/scenario brain
Maintains dependency and sensitivity logic. If a payment assumption, delivery dependency, requirement or timeline changes, downstream decisions are invalidated rather than silently reused.

### Meta-cognition brain
Reviews the reviewers. It blocks missing expertise, producer/judge collision, unresolved dissent, all-PASS groupthink, authority leakage and council theatre.

### Engagement memory
Append-only memory records decisions, assumptions and findings with hashes. Changed upstream inputs mark dependent records stale rather than rewriting history.

### Learning brain
A discovered defect creates a regression proposal: fixture + detector/runtime-required declaration + repair policy + non-regression. It cannot silently mutate protected Skill authorities.

## Artifact search
The old exhibit path hard-coded `winner=H1`. Brain v1.0 removes that authority. Five structural hypotheses are generated from artifact candidates and no winner exists until actual rendered candidates receive independent judgments. QA cannot substitute for the visual judge.

## Release law
- Legacy v3.1 release path cannot produce production RELEASED.
- QA v4.1 can produce only `QA_CANDIDATE_PASS`.
- Final `RELEASED` belongs only to `RASHAD_BRAIN_RELEASE_CHAIR` after brain judgment + QA candidate proof + hard-blocker closure.

## What remains deliberately not claimed
The package does **not** claim live independent model councils have run. A live BrainProvider still has to be connected to the actual Streamlit/OpenAI orchestration. Renderer mechanics such as obstacle-aware connector routing and automatic rail compression are also still a separate remediation track.
