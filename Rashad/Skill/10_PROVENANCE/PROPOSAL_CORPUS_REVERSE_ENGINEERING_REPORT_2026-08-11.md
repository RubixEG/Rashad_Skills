## What the corpus adds beyond the 21 generated-image corpus

The generated-image corpus taught **single-page composition intelligence**. The historical proposal corpus adds **multi-page narrative intelligence**:

1. evaluator-oriented story sequence;
2. section rhythm across 50–220+ pages;
3. transition from understanding to method to evidence;
4. how workstreams are unpacked into activities/outputs/tools;
5. how credibility, team, references, and appendices are staged;
6. how delivery roadmaps, governance, and evidence are layered through a proposal rather than compressed into one page.

## Strong reusable narrative patterns

### NAR-01 — Understanding → Interpretation → Response
Use when the evaluator must see that Rubix has understood the client's context before presenting a solution. Start with client objective/evidence, derive the engagement implication, then present the response architecture.

### NAR-02 — Context → Gap → Target State
Use for transformation, operating-model, digital, quality, and maturity engagements. Avoid generic before/after decoration; the target state must answer the diagnosed gap.

### NAR-03 — Requirement → Method → Output → Acceptance
Strong for RFP-driven technical proposals. It creates a traceable chain from tender requirement to delivery method and proof of completion.

### NAR-04 — Phase Promise → Activities → Tools → Deliverables → Gate
Observed repeatedly in methodology sections. Retain the logic, not the historical cards. Each phase must have a purpose and completion condition.

### NAR-05 — Workstream System → Cross-Dependencies → Integrated Outcome
Use where multiple tracks must operate as one engagement. Stronger than presenting independent service cards.

### NAR-06 — Claim → Evidence → Relevance
Use for credentials/case studies. Historical proposals frequently show evidence, but Rashad must add the explicit relevance bridge to the current evaluation criterion.

### NAR-07 — Executive Thesis → Analytical Detail → Control Layer
Strong for long sections: open with the decision-level conclusion, unpack the mechanism, then show governance/measurement/controls.

## Strong reusable artifact/composition patterns

### ARC-H01 — Strategic Pillar Architecture
A small number of pillars connected to one outcome or north star. Use for strategy, operating model, capability or program logic.

### ARC-H02 — Multi-Track Delivery Architecture
Parallel workstreams aligned to shared milestones/gates. Prefer this to equal cards when dependency matters.

### ARC-H03 — Phase Journey with Output Gates
A directional methodology with explicit phase outputs and decision/acceptance gates.

### ARC-H04 — Capability / Operating Model Hierarchy
Tiered or nested capability structure showing how strategic, operational and enabling layers relate.

### ARC-H05 — Current-to-Target Transformation
Diagnosed current state linked to specific target-state capabilities and transition actions.

### ARC-H06 — Deliverable / Milestone Roadmap
Outputs across time with ownership or acceptance, rather than a decorative timeline.

### ARC-H07 — Governance and Decision Architecture
Decision bodies, operating cadence, escalation and information flow. Must show decision rights, not just organization boxes.

### ARC-H08 — Evidence / Case Study Proof Panel
One claim, quantified/observable evidence, visual proof where relevant, and explicit relevance to the current opportunity.

### ARC-H09 — Stakeholder / Ecosystem Map
Use when stakeholder relationships matter. Historical logo walls are not sufficient; Rashad must encode role/flow/influence.

### ARC-H10 — Executive Metrics Snapshot
A small number of metrics used as proof or decision signals. Avoid decorative number walls.

### ARC-H11 — Workstream-to-Deliverable Matrix
Shows which workstream produces which deliverables, with ownership/acceptance where useful.

### ARC-H12 — Section Navigation / Rhythm Device
Historical proposals used strong section markers and divider pages. Retain the function (orientation and rhythm), not the old magenta/dark visual shell.

## Composition intelligence retained

- one dominant focal point per page;
- clear hierarchy between thesis, artifact, evidence and footnote;
- alternating density across a long section;
- section opener → analytical pages → implementation/control → transition;
- visual system pages should occupy the page rather than be squeezed into small cards;
- tables are appropriate for precise lookup, not for relationships better expressed as systems or flows;
- case-study pages need proof and relevance, not screenshot collections;
- methodology visuals are strongest when outputs/gates are visible, not when phases are only named.

## Historical anti-patterns rejected

1. old Rubix wordmarks/devices as current identity;
2. dark or full-bleed magenta masters used as default section solution;
3. rigid faceted/cube cover grammar as a mandatory current device;
4. company-profile pages placed before client understanding by default;
5. equal-card grids that erase sequence/dependency/importance;
6. dense text boxes with small type;
7. mega-tables or Gantts without an executive reading path;
8. screenshot walls presented as proof without relevance;
9. certificate scans dominating the proposal body instead of an evidence index/appendix;
10. decorative icons/hexagons without analytical purpose;
11. repeated identical layout families across consecutive pages;
12. exact historical page cloning, including coordinates, footer systems, colors and old client branding.
