# Image, Illustration, and Icon System v7.2

## Purpose
Use visual generation to improve proposal strength without sacrificing brand accuracy, editability, factual precision, or Arabic rendering.

## Production asset types
- hero photography;
- editorial/sector illustration;
- conceptual ecosystem illustration;
- abstract background or texture;
- isolated decorative motif;
- icon concept converted to clean SVG;
- approved generated icon in the Rubix family.

## Forbidden content inside generated production imagery
- Rubix or client logos;
- proposal titles, labels, page numbers, tables, or Arabic text;
- signatures, certificates, official seals;
- client-system screenshots or fabricated UI;
- precise architecture labels or compliance references;
- third-party marks and watermarks.

## Full-page generations
Full-page image generation is allowed only in **Concept Mode**. It may guide composition but cannot be used as the final proposal page. The production page must be rebuilt using exact assets and editable text/shapes.

## Icon system
When an approved icon family is mounted or generated-and-registered, it becomes the approved starting system for that engagement. v6.2 ships no SVG icon binaries and must not claim otherwise. All production icons must:
- use consistent geometry and stroke behavior;
- remain visually legible at 18–32 px;
- use `currentColor` to support theme mapping;
- contain no embedded raster images;
- have transparent backgrounds;
- be editable or replaceable in PowerPoint;
- serve a semantic navigation or emphasis role.

## Asset provenance classes
- `OWNED_APPROVED` — owned/approved and reusable.
- `GENERATED_APPROVED` — generated and passed quality/brand review.
- `LICENSED_RESTRICTED` — licensed with documented restrictions.
- `OFFICIAL_PUBLIC` — official/public asset with permitted use.
- `REFERENCE_ONLY` — inspiration/benchmark only.
- `PROHIBITED` — cannot enter production.

## Asset selection priority
1. Exact approved current brand assets.
2. Existing owned/approved asset.
3. Existing generated-approved asset.
4. New generated asset following a page-specific brief.
5. Native vector/shape fallback.

Never select a visually attractive asset whose provenance, identity, or semantic relevance is uncertain.
