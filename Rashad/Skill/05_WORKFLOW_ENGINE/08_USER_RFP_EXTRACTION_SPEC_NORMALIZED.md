# User-Supplied RFP Extraction Requirements — Normalized

Source: `What we need from RFP.docx`. This file converts the supplied checklist into a structure-independent extraction specification.

## Required items
- government entity logo on the summary cover;
- government entity name from definitions or another authoritative identity location;
- last date for questions and clarifications;
- last date for proposal submission;
- award date;
- service commencement date;
- contract duration;
- scope of work;
- place of performance because remote or distant execution may affect cost;
- BOQ, including when it appears only in attachments;
- training and knowledge transfer because it affects resources and cost;
- proposal evaluation criteria, often in attachments;
- team specifications, often in attachments.

## Scope interpretation requirements
- do not rely only on a short or generic introduction;
- use project objectives and core phases to understand the real intent;
- for each phase extract what it contains and its output(s);
- test whether the source phase order is complete and logically coherent;
- when the source order appears wrong, preserve it and create a separate analytical dependency sequence and clarification item.

## Structure flexibility
The original checklist referenced example section numbers. Those numbers are search hints only and are not reusable rules. The engine must locate the information semantically in every new RFP and its annexes.
